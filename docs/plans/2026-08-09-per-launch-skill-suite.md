# Per-launch Pi skill-suite selection Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Keep the canonical `pi` command and shared Pi state unchanged while selecting either Superpowers or Matt Pocock's stable skills per launch, with `pi-matt` as a fixed Matt convenience command.

**Architecture:** Add one generic Nix wrapper constructor that can name its executable, choose a default suite, and allow or disable environment selection. Use it for selectable `pi`, fixed `pi-matt`, and the jailed fixed-Superpowers wrapper; each normal launch loads exactly one immutable suite package and routing prompt before delegating to upstream Pi. Keep one suite-neutral set of global instructions and subagent profiles; persistent Pi settings contain only common packages.

**Tech Stack:** Nix/flake-parts, Home Manager, Bash generated by `pkgs.writeShellApplication`, Python assertions in Nix checks, Pi package/resource discovery, Pi TypeScript extension API for test-only resource probing.

**Authoritative spec:** `docs/specs/2026-08-09-per-launch-skill-suite-design.md`

## Global Constraints

- Platform support remains `x86_64-linux` only.
- Plain `pi` and `ROCHE_PI_SKILLSET=superpowers pi` select Superpowers.
- `ROCHE_PI_SKILLSET=matt pi` selects Matt mode; no other selector value is accepted by selectable `pi`.
- `pi-matt` is a fixed Matt convenience command, ignores `ROCHE_PI_SKILLSET`, and shares the same `~/.pi/agent` state.
- An invalid selector passed to selectable `pi` exits with status 2 before upstream Pi starts; fixed `pi-matt` ignores the selector variable.
- Persistent `settings.packages` must contain neither workflow suite.
- Superpowers must load as a complete package so `.pi/extensions/superpowers.ts` remains active in Superpowers mode.
- Matt mode loads only `skills/engineering/` and `skills/productivity/`; it excludes `skills/in-progress/` and `skills/misc/`.
- Fetch both upstream repositories at Nix evaluation/build time using pinned commits and hashes. Do not use runtime Git URLs or `npx skills add`.
- Preserve `~/.pi/agent` authentication, sessions, trust, models, run history, common extensions, local skills, and settings.
- Do not mutate shared files or symlinks during launch; concurrent Pi processes may select different suites safely.
- Keep `planner`, `worker`, and `reviewer` suite-neutral with `inheritSkills: false`; inject only the skill required by a concrete child task.
- The main Home Manager package and default development shell install selectable `pi` and fixed `pi-matt`. Jailed Pi uses only a fixed Superpowers wrapper and ignores `ROCHE_PI_SKILLSET`.
- Do not add tests for literal hashes, Markdown text, or static profile wording. Verify those with Nix fetch/build checks, targeted searches, and Markdown/diff checks.
- New files referenced by the flake are invisible to ordinary git-backed flake evaluation until staged. Use a `path:` flake for the initial RED run, then stage the files before normal `nix build` or `nix flake check` commands.
- Production wrapper behavior and runtime resource selection require automated checks under the Testing Value Gate.

## Planned File Structure

### New files

- `nix/packages/pi-skillset-wrapper.nix` — the only module that translates a validated skill-set selection into upstream Pi arguments.
- `modules/checks/pi-skillset-wrapper.nix` — isolated behavioral check using a fake upstream Pi executable.
- `modules/packages/pi.nix` — exposes selectable `pi`, fixed `pi-matt`, fixed `pi-superpowers`, and filtered `mattpocock-skills` flake packages.
- `profiles/superpowers/APPEND_SYSTEM.md` — Superpowers-specific Pi/subagent routing adaptations.
- `profiles/matt/APPEND_SYSTEM.md` — Matt-specific Pi/subagent routing adaptations.
- `nix/check-support/pi-skillset-probe.ts` — test-only Pi command that writes discovered skills and appended prompt data as JSON.
- `modules/checks/pi-config-extension-load.nix` — Home Manager-like runtime check for both skill sets.

### Modified files

- `nix/packages/pi-deps.nix` — pin and filter Matt's repository, export both suite derivations, and remove Superpowers from common package paths.
- `AGENTS.md` — retain shared policy while removing permanent Superpowers-only routing.
- `agents/README.md` — document shared suite-neutral role profiles.
- `agents/planner.md` — follow any injected planning skill without requiring `writing-plans` by name.
- `agents/worker.md` — follow any injected TDD/implementation skill without requiring Superpowers names.
- `agents/reviewer.md` — support generic, Standards, and Spec reviews without Superpowers-only wording.
- `agents/code-reviewer.md` — remain disabled while pointing all legacy callers to `reviewer` generically.
- `modules/packages/pi-config.nix` — retain package construction and the Sherpa check; move the expanded extension/resource check to `modules/checks/`.
- `modules/home/pi.nix` — install selectable `pi` and fixed `pi-matt`.
- `modules/devshells/default.nix` — install selectable `pi` and fixed `pi-matt` in the default shell.
- `nix/lib/mk-jailed-pi.nix` — default jailed launchers to the fixed Superpowers wrapper.
- `modules/home/jailed-pi.nix` — use upstream Pi only for version metadata and the fixed wrapper for execution.
- `README.md` — document the selector, fixed `pi-matt` convenience command, and jailed-Pi limitation.

- [ ] **Step 3: Implement the minimal wrapper constructor**

Create `nix/packages/pi-skillset-wrapper.nix`:

```nix
{
  pkgs,
  piPackage,
  skillsets,
  programName ? "pi",
  defaultSkillset ? "superpowers",
  allowSelection ? true,
}:
let
  inherit (pkgs) lib;

  acceptedSkillsets = builtins.attrNames skillsets;
  acceptedSkillsetsText = lib.concatStringsSep ", " acceptedSkillsets;

  skillsetCases = lib.concatStringsSep "\n" (
    lib.mapAttrsToList (
      skillsetName: profile: ''
        ${skillsetName})
          suite_package=${lib.escapeShellArg (toString profile.package)}
          suite_instructions=${lib.escapeShellArg profile.instructions}
          ;;
      ''
    ) skillsets
  );
in
assert lib.assertMsg (builtins.hasAttr defaultSkillset skillsets)
  "default Pi skill set '${defaultSkillset}' is not defined";
pkgs.writeShellApplication {
  name = programName;
  text = ''
    set -euo pipefail

    ${
      if allowSelection then
        ''selected_skillset="''${ROCHE_PI_SKILLSET:-${defaultSkillset}}"''
      else
        ''selected_skillset=${lib.escapeShellArg defaultSkillset}''
    }

    case "$selected_skillset" in
      ${skillsetCases}
      *)
        printf 'pi: unsupported ROCHE_PI_SKILLSET=%s; expected one of: ${acceptedSkillsetsText}\n' \
          "$selected_skillset" >&2
        exit 2
        ;;
    esac

    case "''${1:-}" in
      install|remove|uninstall|update|list|config|auth|--help|-h|--version|-v|--list-models)
        exec ${lib.getExe piPackage} "$@"
        ;;
    esac

    exec ${lib.getExe piPackage} \
      --extension "$suite_package" \
      --append-system-prompt "$suite_instructions" \
      "$@"
  '';
  meta.mainProgram = programName;
}
```

Keep selection as a closed enum. Do not accept an environment-provided path and do not use `eval`.

Create `nix/check-support/pi-skillset-probe.ts`:

```typescript
import { writeFileSync } from "node:fs";
import type { ExtensionAPI } from "@earendil-works/pi-coding-agent";

const BOOTSTRAP_MARKER = "superpowers:using-superpowers bootstrap for pi";
const STOP_MARKER = "PI_SKILLSET_PROBE_STOP";

export default function (pi: ExtensionAPI) {
  const bootstrapOutput = process.env.PI_SUPERPOWERS_BOOTSTRAP_OUTPUT;

  pi.registerCommand("write-skillset-probe", {
    description: "Write loaded skill-set resources for a Nix runtime check",
    handler: async (_args, ctx) => {
      const output = process.env.PI_SKILLSET_PROBE_OUTPUT;
      if (!output) {
        throw new Error("PI_SKILLSET_PROBE_OUTPUT is required");
      }

      const options = ctx.getSystemPromptOptions();
      writeFileSync(
        output,
        JSON.stringify({
          skills: (options.skills ?? []).map((skill) => skill.name).sort(),
          appendSystemPrompt: options.appendSystemPrompt ?? "",
        }),
      );
    },
  });

  pi.on("context", async (event) => {
    if (bootstrapOutput && event.messages.some(messageContainsBootstrap)) {
      writeFileSync(bootstrapOutput, `${BOOTSTRAP_MARKER}\n`);
    }
  });

  pi.on("before_provider_request", () => {
    if (bootstrapOutput) {
      throw new Error(STOP_MARKER);
    }
  });
}

function messageContainsBootstrap(message: unknown): boolean {
  const content = (message as { content?: unknown }).content;
  if (typeof content === "string") {
    return content.includes(BOOTSTRAP_MARKER);
  }
  if (!Array.isArray(content)) {
    return false;
  }
  return content.some((part) => {
    return (
      part &&
      typeof part === "object" &&
      (part as { type?: unknown }).type === "text" &&
      typeof (part as { text?: unknown }).text === "string" &&
      (part as { text: string }).text.includes(BOOTSTRAP_MARKER)
    );
  });
}
```

The `/write-skillset-probe` command inspects resources without invoking a provider or model. The separate bootstrap observation enters the agent pipeline, records the marker injected by the Superpowers `context` handler, and then aborts in `before_provider_request` before any network call.
